## Средний приоритет

### EPUB-сборка
**Что:** `_build_epub` в `lib_bgen.py`, секция `epub:` в `config.yaml`
(`enabled`, `output_name`, `css`), `KNOWN_FORMATS`. Тот же `body/`, тот же
`filter_bgen.lua` (для EPUB возвращает `nil`, оставляя `Div`/`Span`), CSS.
**Зачем:** EPUB — «книга для читателя» (международный формат). Фильтр готов,
нужен CSS и вызов Pandoc `-t epub3`.
**Сложность:** низкая.

### CSS для EPUB
**Что:** `epub.css` с правилами для `.epigraph`, `.annotation`, `.poem`
(LineBlock), `.q`/`.qq`, `.subtitle`, `.asterism`.
**Зачем:** без CSS EPUB «голый». CSS делает EPUB книгой.
**Сложность:** низкая.

### Обложка EPUB
**Что:** `metadata.cover-image` → `--epub-cover-image`.
**Зачем:** обложка — первое, что видит читатель.
**Сложность:** низкая.

### `sequence` в EPUB
**Что:** `sequence` из `config.yaml` → `calibre:series` meta / `belongs-to-collection`
в OPF.
**Зачем:** для циклов (художка часто серийная) — критично.
**Сложность:** средняя.

### `description.xml` для EPUB/DOCX?
**Что:** решить, нужен ли аналог (OPF-метаданные, `core.xml`). Пока неясно.
**Сложность:** средняя.

## Низкий приоритет (отложено)

### `config.schema.json` + валидация
**Что:** JSON Schema для `config.yaml`, валидация через `jsonschema` на старте.
**Зачем:** централизованная проверка типов вместо ручных проверок в коде.
**Когда:** после DOCX/EPUB (структура стабилизируется, станет ясно, какие
поля общие, а какие — формат-специфичные).

### `check` — health check проекта
**Что:** `bgen.py check <path>` — проверяет **всё, что есть** (независимо от
`config.yaml`): `config.yaml` (валидность), `body/` (не пусто), `fb2_description.xml`
(well-formed, наличие секций), `img/` (файлы существуют). **Сообщает**, не падает.
**Зачем:** «всё ли в порядке с проектом» до сборки.

### TOC для EPUB/DOCX
**Что:** для EPUB Pandoc генерирует `nav.xhtml` всегда (не нужно). Для DOCX —
`--toc` (поле TOC, обновляется в Word).
**Зачем:** «коммерческий» вид EPUB/DOCX.
**Сложность:** низкая (для DOCX).

### Внутренние ссылки между файлами
**Что:** проверить/задокументировать, что `--file-scope` ломает ссылки между
файлами. Либо отказаться от `--file-scope` (склеивать в один), либо
документировать ограничение.
**Зачем:** в публицистике ссылки между главами — часто.
**Сложность:** средняя.

+++ Статистика по главам (проверка структуры, а не стиля).
+++ Типографический linter — это про сборку, а не про анализ. Он проверяет, что разметка корректна до того, как
    Pandoc её обработает: нет ли прямых " (которые smart превратит в “” вместо «»), нет ли --/..., если автор хотел
    явные символы. Это предотвращает ошибки сборки, а не анализирует стиль. Его место в bgen — оправдано.


### Сноски с форматированием
**Что:** проверить, что сноски с несколькими абзацами/списками/стихами
корректно генерируются в `<body name="notes">` и проходят XSD.
**Зачем:** в публицистике сноски сложные.
**Сложность:** средняя.

### Тесты (pytest)
**Что:** тесты на `_make_book_id`, `_apply_custom_description`,
`_update_book_anno_and_epi_from_body`, `_sort_children_by_order`, фильтр
(через вызов Pandoc на минимальном проекте).
**Зачем:** без тестов изменения в постобработке могут сломать FB2 незаметно.
**Когда:** параллельно с EPUB, чтобы не накапливать долг.

### `--keep-metadata` / `--list-files`
**Что:** флаги для отладки: сохранить `metadata.yaml`, показать порядок файлов.
**Зачем:** когда что-то идёт не так, полезно видеть, что ушло в Pandoc.
**Сложность:** низкая.

### Валидация через `xmlschema` вместо `lxml`
**Что:** `xmlschema` показывает **все** ошибки XSD, а не первую.
**Зачем:** удобство отладки.
**Сложность:** низкая.

### `--keep-going` для сборки нескольких форматов
**Что:** ошибка в одном формате не прерывает сборку остальных.
**Зачем:** при сборке FB2+EPUB+DOCX.
**Сложность:** низкая.

### `export-txt`
**Что:** `bgen.py export-txt <path> --width 80 --typographic` — плоский текст
(карточка в начале, заголовки, эпиграфы, текст).
**Зачем:** TXT — базовый формат (Kindle без Send to Kindle, архив, инструменты
без FB2).
**Сложность:** низкая.

### Числовая сортировка `chapter_*`
**Что:** сортировать по числу из имени (`re.search(r"\d+", p.name)`), а не
лексикографически (чтобы `chapter_10` не был раньше `chapter_2`).
**Зачем:** при 10+ главах порядок сбивается.
**Сложность:** низкая.

### Стили (`style` и `<stylesheet>`)
**Что:** `::: {.style name="letter"}` → `<p style="letter">`, плюс
`<stylesheet>` в `description`.
**Зачем:** письма, документы, телеграммы в художке; «врезки» в публицистике.
**Сложность:** высокая, непредсказуемо в читалках.

### Таблицы с colspan/rowspan
**Что:** либо ограничиться простыми таблицами (задокументировать), либо
постобработка (хрупко).
**Зачем:** в публицистике — обычное дело.
**Сложность:** высокая (ограничение Pandoc).

### Вложенные `<sequence>`
**Что:** не поддерживать (не по схеме FB2; «де-факто» расширение FBE).
**Зачем:** официальная схема не предусматривает вложенность.

## Не делать

- **Spellcheck** — есть сторонние сервисы с недостижимым качеством.
- **PDF для печати** — ручная работа (формат полосы, поля, шрифты, висячие
  строки). Максимум — DOCX с чистыми стилями как заготовка для верстальщика.
- **Планирование/outlining, focus mode, синхронизация/облако, AI-ассистент** —
  это не про сборку книги. `bgen` не должен становиться редактором.
- **Проверка повторов слов, частотность сверх топ-20, «стилевые» рекомендации** —
  это редакторские инструменты, вне концепции `bgen` (отдельный скрипт).
- **MOBI/AZW3** — Amazon сам конвертирует EPUB при Send to Kindle.
- **Мерж `description.xml` с `config.yaml`** — `template` покрывает 90% случаев.
