## FB2: постобработка

### Списки

**Проблема.** Pandoc 3.1.3 намеренно выводит списки в FB2 как последовательность
`<p>` с маркерами (`• `, `1. `), а не как `<unorderedlist>`/`<orderedlist>`.
Это осознанное решение авторов FB2-writer'а: отступы пробелами не рендерятся
в FBReader и fbless, поэтому маркеры добавляются прямо в текст.
См. коммиты Pandoc, где `el "p" $ txt (mrk ++ " ")` и пояснение про FBReader.

**Следствие.** Валидный XML, но семантически список потерян: читалка показывает
абзацы с маркерами, а не список. Для художественной литературы часто приемлемо,
для нон-фикшна — плохо.

**Что сделать.** Добавить постобработку с эвристикой:
- находить последовательности из **двух и более** `<p>` подряд, начинающихся
  с `• ` (unordered) или `N. ` (ordered);
- собирать их в `<unorderedlist>`/`<orderedlist>` с `<listitem><p>…</p></listitem>`;
- одиночный `<p>` с маркером не трогать (снижает риск ложных срабатываний).

**Опционирование.** Добавить в `config.yaml` в секцию `fb2:` флаг
`fix_lists: true` (по умолчанию `true`). Если эвристика ошибётся на реальном
тексте — можно отключить и оставить поведение Pandoc.

**Риск.** Абзац, начинающийся с `• ` или `1. ` как часть повествования,
может быть ошибочно принят за список. Митигация: требовать 2+ подряд,
документировать в README.

## Прочее

### Числовая сортировка `chapter_*`

**Проблема.** `iter_text_files` сортирует лексикографически. При 10+ главах
`chapter_10` окажется раньше `chapter_2`.

**Что сделать.** Сортировать по числу, извлечённому из имени
(`re.search(r"\d+", p.name)`), с fallback на лексикографическую сортировку,
если числа нет.

---

### EPUB / DOCX

**Проблема.** Секции `epub:`/`docx:` в `config.yaml` закомментированы,
веток в `build()` нет.

**Что сделать.** Расширить `KNOWN_FORMATS`, добавить `_build_one_epub()` /
`_build_one_docx()`, соответствующие секции в конфиге.
Для эпиграфов в EPUB — `div.epigraph` + CSS; в DOCX — `custom-style="Epigraph"`
+ стиль в `reference.docx`.

---

### `--keep-going` для сборки нескольких форматов

**Проблема.** Ошибка в одном формате прерывает всю сборку, даже если
предыдущие форматы уже собрались.

**Что сделать.** Добавить флаг `--keep-going`, который собирает список
ошибок вместо исключения.

---

### `--keep-metadata` для отладки

**Проблема.** Пользователь не может увидеть временный `metadata.yaml`,
который генерируется для Pandoc.

**Что сделать.** Добавить флаг `--keep-metadata`, который сохраняет
временный файл в `output_dir` для отладки.

Техническое задание на bgen

1. Цель
Генерация цифровых книг из исходников (текст в Markdown, картинки) с корректным тегированием целевых форматов.
Форматы по этапам:
FB2 — первый этап, наиболее распространён в русскоязычном сегменте.
DOCX — далее, для отправки и подготовки макета.
EPUB — далее, международный стандарт.
PDF — не делаем: подготовка макета для печати — отдельная большая задача.

2. Требования
Кроссплатформенность: Windows и Linux. Стек — Python + Pandoc.
Минимум внешних инструментов: Pandoc + PyYAML. Всё остальное — стандартная библиотека Python.
Статистика текста: знаки с/без пробелов, слова, уникальные слова, топ-20 частотных.
Отдельное хранение текстов и ресурсов.
Пример проекта, который можно скопировать и переработать.
Не делать: spellcheck (есть сторонние сервисы с недостижимым качеством).

Правила body/:

Внутри body/ — только текстовые .md файлы. Служебных файлов нет.

Обход рекурсивный, сортировка лексикографическая по полному пути.

Разделения small_form.md vs big_form/ больше нет: один файл в body/ — вырожденный случай многих файлов.

Уровень заголовка = уровень вложенности: ## для верхнего уровня body/, ### внутри chapter_*/, #### глубже. # (первый уровень) в body/ не используется — заголовок книги живёт в metadata.title и попадает в <book-title>.

Служебное — на уровне text/:

_annotation.md — аннотация книги. Читается отдельно, вставляется постобработкой в <title-info>/<annotation>.

Решения по конфигу:

Все поля, относящиеся к FB2 (включая постобработку), — в секции fb2:. Верхнеуровневой postprocess: нет.

Присутствие секции с enabled: true = формат собирается.

output_name — свойство формата, а не проекта.

date: одно поле, не пара force_date + date. Если задано — используется; иначе — сегодняшняя дата (идемпотентно, существующий fb:date перезаписывается).

Обязательные поля проверяются в библиотеке; отсутствие title/author — BgenError.

7. Семантическая разметка в Markdown
Эпиграфы — единый механизм для книги и глав
markdown
Copy
Download
::: {.epigraph}
Текст эпиграфа.

— Иван Петров
:::
Эпиграф книги: первый файл в body/ (например, 00_epigraph.md), до первой секции.

Эпиграф главы: в первом файле главы (chapter_0/00_scene.md) или отдельным 00_epigraph.md внутри главы.

Автор — вторая часть через пустую строку; постобработка выносит в <text-author>.

FB2: постобработка заменяет Div.epigraph на <epigraph><p>…</p><text-author>…</text-author></epigraph>. Различение книга/глава — по позиции в дереве (до первой <section> = книга).

EPUB: div.epigraph + CSS (без спецобработки).

DOCX: custom-style="Epigraph" + стиль в reference.docx.

Ограничения FB2, которые нужно знать авторам
Элемент	В FB2 через Pandoc	Как быть
Эпиграф	Не генерируется, Div прозрачен	::: {.epigraph} + постобработка
Разрыв строки внутри абзаца	Невозможен по схеме FB2	Не использовать
Пустая строка между абзацами	HorizontalRule --- → <empty-line/>	--- отдельной строкой, с пустыми строками до/после
Сильный разделитель (* * * визуально)	* * * тоже HorizontalRule, в FB2 нет разницы	::: {.asterism} + постобработка (если понадобится)
Многострочный код	Нет в схеме; Pandoc выдаёт серию <p><code>	Принять ограничение, не добавлять ::: {.code}
Стихи	<poem>/<stanza>/<v> не генерируются	LineBlock или ::: {.poem} + постобработка (позже)
Таблицы	Простые работают, сложные/без заголовков — нет	Тестировать в syntax_demo.md, использовать работающие
<title> внутри <body>	Не использовать; заголовок книги — в <book-title>	# в body/ не писать
8. Постобработка FB2 (обязательна)
Выполняется всегда: без неё FB2 от Pandoc невалиден. Всё на Python (xml.etree.ElementTree), без Lua.

Что делает _postprocess_fb2:

genres — удаляет unrecognised/существующие, вставляет из fb2.genres (или unrecognised).

annotation — удаляет все <annotation> из title-info, вставляет из _annotation.md (разбивка по пустым строкам на <p>).

document-info — гарантирует <id>, <version>, <date>; дата из fb2.date или сегодня.

epigraphs — Div.epigraph → <epigraph> с <p> и <text-author>. Различение книга/глава по позиции.

pretty_print — ET.indent (опционально, из fb2.pretty_print; на Python < 3.9 молча пропускается с предупреждением в warnings).

Обложка: путь metadata.cover-image резолвится относительно корня проекта в абсолютный, передаётся в Pandoc через временный metadata.yaml.

Возврат: _postprocess_fb2 возвращает список предупреждений (не печатает).

9. Статистика
Читает только содержимое body/ (служебный _annotation.md не учитывается).

strip_markdown — грубое удаление разметки (заголовки, ссылки, изображения, код, *_~).

Возвращает dict: files, chars_with_spaces, chars_no_spaces, words, unique_words, top (20 пар).

Печать — только в bgen.py.

10. Что осталось за кадром / на будущее
Числовая сортировка chapter_* — обсуждалась; сейчас лексикографическая сортировка, при 10+ главах chapter_10 окажется раньше chapter_2. Решение (числовая сортировка по извлечённому числу) не реализовано.

:asterism для визуально сильного разделителя — не реализовано, * * * пока даёт <empty-line/>.

:poem для стихов — не реализовано.

Валидация FB2 по XSD — отложена; сейчас проверяется только парсинг XML и наличие title-info.

EPUB / DOCX — секции в конфиге закомментированы, ветки в build() нет.

--keep-going для сборки нескольких форматов при ошибке в одном — не реализовано; сейчас ошибка в любом формате прерывает всю сборку.

--keep-metadata для отладки Pandoc — не реализовано.
