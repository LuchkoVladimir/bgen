# Пример проекта книги bgen

Скопируйте этот каталог и используйте как основу для новой книги.

## Запуск

    bgen.py build .
    bgen.py stat .
    bgen.py cfg .
    bgen.py check .

## Структура

    config.yaml          - конфигурация проекта (все параметры с комментариями)
    body/                - весь текст книги
    img/                 - директория для храниения изображений книги
    img/cover.jpg        - обложка (положите любой .jpg)
    fb2_description.xml  - пример хедера fb2 для тонкой настройки description
    output/              - будет создана для собранных форматов, если оставить настройку в config.yaml как есть
    readme.md            - этот файл, в работе bgen не участвует, нужен только для информации

# Как собирается текст

Все `.md` файлы в `body/` **рекурсивно** обходятся, сортируются
лексикографически по полному пути и склеиваются в один документ.
Такой обход отображается `ls`

- Один файл в `body/` - рассказ в одном файле.
- Много файлов и поддиректорий - большая форма.
- Разницы в механике сборки нет.

Пример многофайловой структуры:

    body/
      000_epigraph.md         # эпиграф книги
      010_partone.md          # ## Часть первая
      020_parttwo.md          # ## Часть вторая
      030_chapter/
        000_scene.md          # ### Сцена
      040_chapter/
        000_scene.md

**Порядок лексикографический, по полному пути** (Python сортирует по code
point, не по локали). Для предсказуемого порядка используйте ASCII-имена
с ведущими нулями (`00_`, `01_`, `09_`, 0a_, 0b_...). Кириллица в именах может дать
неожиданный порядок. В числах лучше оставлять пропуски, чтобы было проще вставлять новые части.

## Особенности

**Не смешивайте текст и подсекции в одной секции.** Если в главе есть
подглавы (`###`), текст между `##` и первым `###` писать нельзя — XSD
ругается на смешанную секцию. Либо текст до `##`, либо глава состоит
только из подглав. Это ограничение формата FB2, многие читалки всё
равно отобразят такой файл, но это уже на ваш страх и риск.

## Специальная разметка

Примеры **всех** конструкций (эпиграфы, аннотации, фронтиспис, subtitle,
астеризм, стихи, кавычки, сноски, ссылки, таблицы, списки) - в `body/99_syntax_demo.md`.
Соберите пример (`bgen.py build .`) и посмотрите `output/`: там видно, во что превращается каждая
конструкция.

## Обложка

Положите любой `.jpg` в `img/cover.jpg`. Если файла нет — сборка
продолжится без обложки (с предупреждением).

## Ограничения FB2

- **Разрыв строки внутри абзаца** - невозможен по схеме.
- **Сложные таблицы** (colspan/rowspan) - не поддерживаются Pandoc.
- **Смешанные секции** (текст + подсекции) - XSD не пропускает.

Если хотите генерировать хорошие **FB2** стоит разобраться с форматом. В нём довольно много ограничений. Цель `bgen`
предоставить возможность генерировать корректный **FB2** во всём спектре допустимого. Это накладывает отпечаток на
количество настроек.

## Кастоимзация сборки

Есть два уровня кастоимзации:

### Конфигурационный файл (config.yaml)

Здесь собрана наиболее востребованные возможности. То, что пользователь скорее всего будет менять и настраивать под
конкретный проект. Вся документация на конфигурацию находится в том же `config.yaml` рядом с параметрами - читайте
стандартный файл и редактируйте под себя.

### Конфигурационные шаблоны (fb2_description.xml, epub_metadata.xml, epub.css, reference.docx, typography.txt, rules.txt)

Это "тяжёлая артиллерия" - когда первого уровня недостаточно, этими файлами можмо сделать всё остальное (доступное на
данный момент в `bgen`).

- **typography.txt** - здесь описаны типографские замены. Описание формата в самом файле. Работает для всех
выходных форматов. Дефолт лежит в `bgen/schemas/typography.txt`, но можно положить в проект свой файл и указать к нему
путь в `config.yaml`.
- **rules.txt** - здесь описаны правила поиска (регекспы). Описание формата в самом файле. Ищет по указанным шаблонам
в md-исходнике. Проверка на соблюдение некоторых правил русской типографики. Дефолт лежит в `bgen/schemas/rules.txt`,
но можно положить в проект свой файл и указать к нему путь в `config.yaml`.
- **fb2_description.xml** - файл для детальной настройки заголовка **FB2**. Можно использовать в режиме шаблона (`template`),
когда в итоговый заголовой попадает то, что сгенерировал `bgen` и разложил по указанным в шаблоне местам или, если `bgen`
это не генерировал, то, что прописал пользователь в шаблоне. Второй режим - перезаписи (`override`). В этом режиме файл
перезаписывает заголовок как есть, без генераций `bgen`. Как выставляются и переключаются режимы - описано в `config.yaml`.
Стандартного файла bgen здесь нет, так как он для специфических запросов. Но пример такого файла приложен в проект книги.
- **epub_metadata.xml** - аналогичный файл для **EPUB**. Стандартного нет по той же причине и к проекту книге примера не
приложено (возможно позже). Для понимания что и как в нём писать - обратитесь к документации `pandoc --epub-metadata`.
Настройки путей к файлу и режима сборки **EPUB** с ним или без него - в `config.yaml`.

Следующие файлы определяют стили для генераций.

- **epub.css**. Стили для **EPUB**. То, что добавляет `bgen` описано в `bgen/schemas/epub.css`. Это же и стандартный
файл, используемый для генерации. Но можете написать свой, положить в проект книги и указать к нему путь в `config.yaml`.

- **reference.docx**. Стили для **DOCX**. Стандартный файл лежит в `bgen/schemas/reference.docx`. Аналогично с предыдущим,
можно написать свой и положить в директорию проекта книги. Редактировать такой файл удобнее всего с помощью
`libreoffice/word`. От `bgen` добавляются и используются следующие стили (`custom-style`):
    - `Epigraph` - из fenced-div в md `epigraph`
    - `EpigraphAuthor` - из fenced-div в md `text-author`
    - `Abstract` - из fenced-div в md `annotation`
    - `Subtitle` - из fenced-div в md `subtitle`
    - `Asterism` - из fenced-div в md `asterism`
    - `Gap` - из fenced-div в md `gap`
